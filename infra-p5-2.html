PHASE 5 · 5.2

🤖 에이전트 호출 규칙

"내가 직접 할까, 보조 일꾼에게 넘길까" — 위임 게이트와 모델 3단 분류.

뭔가요큰 일을 보조 일꾼(에이전트)에게 떼어 맡기는 것.
안 하면모든 걸 메인이 직접 해서, 긴 탐색 결과가 대화 맥락을 잡아먹습니다.
하면일꾼이 따로 일하고 요약만 가져와 메인 맥락이 깨끗해집니다.
주의위임 한 번에 고정 비용(약 16K~25K 토큰)이 들어, 작은 일은 직접 하는 게 이득.
① 위임 게이트

모델을 고르기 전에 "넘길지 말지"부터 판단합니다. 기준은 "코드냐"가 아니라 독립성·규모·맥락 격리예요.

조건처리
독립 항목 3개 이상 (서로 의존 없음·다른 파일)병렬 위임 (fan-out)
대량 탐색·파싱 (다수 파일·로그 읽기)위임 (메인 맥락 격리)
단일 파일 + 20줄 이하 단순 수정메인이 직접 (위임 면제)
디버깅·판단·설계 주도메인 Opus 직접

위임하기로 했다면 일의 성격에 맞는 모델을 고릅니다.

💡
왜 "코드면 위임"이 아닌가
예전엔 "코드 작업 = Sonnet 위임"으로 봤지만, 실제론 대부분 디버깅 주도 + 1~2줄 편집이라 위임 면제에 걸렸습니다. 그래서 2026-05-28에 기준을 "코드냐"에서 변경량 + 판단 비중 + 독립 항목 수로 다시 정의했습니다. 의존 관계가 있는 일(B가 A의 결과 필요)은 병렬 이득이 없어 직렬이나 직접이 낫습니다. (근거: Anthropic "Building Effective Agents")
